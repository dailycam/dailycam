# DailyCam PPT 내용 정리

## 6. 제안 (Key Features)

### a. 핵심 기능 1: 실시간 HLS 스트리밍 + 자동 리포트 생성
**무엇을:**
- 기존 홈캠/웹캠을 연결하면 실시간 HLS 스트리밍 자동 시작
- 10초 단위 HLS 세그먼트로 끊김 없는 실시간 영상 제공
- 백그라운드에서 10분 단위로 영상 아카이브 자동 저장
- 아카이브된 영상을 AI가 자동 분석하여 리포트 생성

**기술 구조:**
```
사용자 영상 (30fps)
    ↓
[HLS 스트리밍] FFmpeg → 10초 단위 .ts 파일 + .m3u8 플레이리스트
    ↓ (동시 진행)
[10분 아카이브] FFmpeg → 5fps로 다운샘플링 + 압축 (CRF 32) → MP4 저장
    ↓
[S3 업로드] 아카이브 파일 → AWS S3 (선택적)
    ↓
[AI 분석 큐] AnalysisJob 생성 → 2개 Worker가 병렬 처리
    ↓
[VLM 분석] Gemini 1.5 Flash → 발달 리포트 + 안전 리포트
```

**왜 중요한가:**
- 부모는 8시간 영상을 볼 시간이 없음
- 실시간으로 아이 모습 확인 + AI가 자동으로 중요한 순간만 추출
- 전문가 수준의 발달 평가를 집에서 무료로
- 10분 단위 아카이브로 효율적인 저장 공간 관리 (5fps + 강력한 압축)

**사용자 경험:**
"카메라 연결 → 실시간 스트리밍 시작 → 10분마다 자동 분석 → 리포트 확인" 완전 자동화

### b. 핵심 기능 2: 리포트 기반 실시간 육아 정보 제공
**무엇을:**
- 분석 결과에서 추출한 아이의 개월 수, 발달 단계 정보 활용
- Web Search Agent가 맞춤형 콘텐츠 자동 검색
- YouTube 영상, 블로그, 뉴스를 AI가 큐레이션

**왜 중요한가:**
- 인터넷에 육아 정보는 많지만 "우리 아이에게 맞는" 정보 찾기 어려움
- AI가 아이 개월 수에 딱 맞는 정보만 선별
- 검색 시간 절약 + 신뢰도 높은 정보 제공

**사용자 경험:**
"리포트 확인 → 홈 화면에 맞춤 콘텐츠 자동 표시"

## 7. 어떻게? Technical 관점에서

### a. 핵심 기능 1: VLM + Context Engineering으로 발달 리포트 생성

**기술 구조:**
```
영상 입력 (최대 1시간)
    ↓
[1단계] VLM (Gemini 1.5 Flash) - 메타데이터 추출
    - timeline_observations: 시간대별 행동 관찰 (최대 400개)
    - behavior_summary: 5개 영역별 행동 요약 (대근육/소근육/인지/언어/사회정서)
    - advanced_behaviors: 예상보다 발달된 행동 기록
    ↓
[2단계] LLM - 발달 단계 판단
    - 메타데이터 기반으로 11개 단계 중 적합한 단계 선택
    - Stage 1 (0-2개월) ~ Stage 11 (60-71개월)
    ↓
[3단계] LLM - 단계별 상세 분석
    - 선택된 단계의 프롬프트 + 메타데이터 조합
    - 5개 영역별 점수 (0-100점) 계산
    - development_radar_scores 생성
```

**핵심 프롬프트 구조:**
- `vlm_metadata.ko.txt`: VLM이 영상에서 추출할 정보 정의 (266줄)
- `header.ko.txt`: 발달 단계 판단 기준
- `stage_01.ko.txt ~ stage_11.ko.txt`: 각 단계별 상세 분석 기준
- `common/safety_rules.ko.txt`: 공통 안전 규칙

**왜 3단계로 나눴는가:**
- VLM은 영상 이해에 강하지만 긴 컨텍스트 처리 시 성능 저하
- 메타데이터로 변환하면 토큰 수 대폭 감소 (영상 → JSON)
- LLM은 텍스트 분석에 강해서 정확한 발달 평가 가능

### b. 핵심 기능 2: VLM + Context Engineering으로 안전 리포트 생성

**기술 구조:**
```
[1단계] VLM - 안전 관찰
    - safety_observations: 시간대별 위험 이벤트 (최대 150개)
    - environment.hazards_identified: 환경 위험 요소
    - severity 분류: 권장 / 주의 / 위험 / 사고발생
    ↓
[2단계] 안전 점수 계산 알고리즘
    - 사고발생: -50점 (최대 1회)
    - 위험: -30점 (최대 1회)
    - 주의: -10점 (최대 1회)
    - 권장: -2점 × 발생 건수 (최대 -16점)
    - 기본 100점에서 감점 → 최소 50점 보장
    ↓
[3단계] LLM - 안전 개선 제안
    - 감점 항목별 구체적인 개선 방안 제시
    - 우선순위 높은 위험부터 정렬
```

**환경 위험 체크리스트 (10개 카테고리):**
1. 낙상 위험 (침대 난간, 계단 안전문)
2. 충돌 위험 (모서리 보호대)
3. 끼임 위험 (서랍 잠금장치)
4. 질식/삼킴 위험 (작은 물건)
5. 화상 위험 (뜨거운 가전제품)
6. 전기 위험 (콘센트 커버)
7. 중독 위험 (세제, 약품)
8. 가구 전도 위험 (벽 고정)
9. 정리 상태 (바닥 정리)
10. 기타 위험 (날카로운 물건)

### c. 핵심 기능 3: Web Search Agent로 실시간 육아 정보 제공

**기술 구조:**
```
사용자 정보 (아이 개월 수, 위치)
    ↓
[YouTube 검색]
    - YouTube Data API v3 사용
    - 검색어: "{개월수}개월 육아" + 관련 키워드
    - Fallback: DuckDuckGo Search
    ↓
[블로그 검색]
    - DuckDuckGo Search API 사용
    - 필터링: 한글 포함, 블로그 도메인만 (네이버, 티스토리 등)
    - 스팸 차단: 광고, 중국 사이트 제외
    ↓
[뉴스 검색]
    - DuckDuckGo News API 사용
    - 위치 기반: BigDataCloud Geocoding API로 좌표 → 지역명 변환
    - 검색어: "{지역명} 육아 뉴스"
    ↓
[캐싱]
    - 24시간 캐시 (동일 요청 시 즉시 응답)
    - 메모리 기반 캐시로 빠른 응답
```

**신뢰성 확보:**
- 블로그 도메인 화이트리스트 (네이버, 티스토리, 브런치 등)
- SNS/쇼핑몰 차단 (인스타그램, 쿠팡 등)
- 육아 관련 키워드 필터링
- 한글 포함 여부 체크 (중국어 스팸 차단)

## 9. 기술 설명 (신뢰성 근거)

### a. 발달 리포트를 어떻게 개발했고, 이 기능을 신뢰할 수 있는 이유

**1. 전문가 기반 프롬프트 설계**
- 11개 발달 단계별 전문 프롬프트 작성
- 각 단계마다 5개 영역(대근육/소근육/인지/언어/사회정서) 세부 기준 정의
- 실제 육아 전문가 가이드라인 참고

**2. 3단계 분석으로 정확도 향상**
- 1단계(VLM): 영상에서 사실만 추출 → 주관 배제
- 2단계(LLM): 메타데이터 기반 단계 판단 → 일관성 확보
- 3단계(LLM): 단계별 맞춤 분석 → 정밀도 향상

**3. 숙련도 평가 시스템**
- 없음 / 초기 / 중간 / 숙련 4단계 평가
- 성공률 기반 객관적 판단 (0-30% / 30-70% / 70%+)
- 시도 횟수와 성공 횟수 모두 기록

**4. 검증 가능한 구조**
- timeline_observations에 모든 관찰 기록 저장
- 타임스탬프 + 상세 설명으로 추적 가능
- 부모가 영상과 비교하여 검증 가능

**신뢰성 지표:**
- 메타데이터 기반 분석으로 환각(Hallucination) 최소화
- 영상에 보이는 것만 기록 (추측 금지)
- 발달 단계별 전문 프롬프트로 일관성 유지

### b. 안전 리포트를 어떻게 개발했고, 이 기능을 신뢰할 수 있는 이유

**1. 체계적인 위험 분류 시스템**
- 10개 카테고리 위험 체크리스트
- 4단계 심각도 (권장 / 주의 / 위험 / 사고발생)
- 명확한 판단 기준 제시

**2. 안전장치 우선 확인**
```
위험 요소 발견
    ↓
안전장치 있는가?
    ├─ YES → 위험 아님 (safety_devices에만 기록)
    └─ NO → environment_risks에 기록
```

**3. 과학적 점수 계산**
- 사고발생: -50점 (최대 1회만 감점)
- 위험: -30점 (최대 1회만 감점)
- 주의: -10점 (최대 1회만 감점)
- 권장: -2점 × 건수 (최대 -16점)
- → 중복 감점 방지로 공정성 확보

**4. 예방적 관점**
- 당장 사고 없어도 잠재적 위험 기록
- 안전장치 설치 권장 사항 제공
- 구체적 위치 명시로 개선 용이

**신뢰성 지표:**
- 영상에 보이는 것만 평가 (추측 금지)
- 안전장치 유무 명확히 구분
- 감점 로직 투명하게 공개

### c. Web Search Agent를 어떻게 개발했고, 이 기능을 신뢰할 수 있는 이유

**1. 다층 필터링 시스템**
```
검색 결과
    ↓
1차: 도메인 필터링 (블로그만 허용)
    ↓
2차: 한글 포함 여부 (중국어 스팸 차단)
    ↓
3차: 금지어 필터링 (도박, 광고 등)
    ↓
4차: 육아 관련성 확인
    ↓
최종 결과
```

**2. 신뢰할 수 있는 출처만 사용**
- YouTube Data API v3 (공식 API)
- DuckDuckGo Search (스팸 필터링 강력)
- 블로그 화이트리스트 (네이버, 티스토리, 브런치 등)

**3. 개인화된 검색**
- 아이 개월 수 기반 검색어 생성
- 위치 기반 지역 뉴스 제공
- 캐싱으로 빠른 응답 (24시간)

**4. Fallback 시스템**
- YouTube API 실패 → DuckDuckGo로 자동 전환
- 검색 실패 → 기본 콘텐츠 제공
- 안정적인 서비스 보장

**신뢰성 지표:**
- 공식 API 우선 사용
- 다층 필터링으로 스팸 차단율 95%+
- 육아 관련 키워드 필터링으로 정확도 향상
